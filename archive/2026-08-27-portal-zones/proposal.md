# 提案：工作台首页拆分为「经营管理 / 运维管理」双分区

> 变更编号：`2026-08-27-portal-zones`
> 作者：AI 编程助手 | 日期：2026-08-27 | 状态：已实现并归档（delta 已合并至 `specs/009-portal-zones/spec.md`）

## 背景与问题

门户首页（`/` → `#page-portal`）目前是**一个扁平的 6 卡网格**，把财经经营类分析（回款周期、资金占用、签单毛利率、项目决算报告、采购合同比对）和运维执行类智能体（备品备件采购询比价）混排在同一层，用户无法从布局上判断「哪些是看经营数据的、哪些是干运维流程的」。

随着 CC-010「项目全生命周期管理」上线，经营侧卡片将增加到 7 张、且下辖 7 个子模块，扁平网格会进一步失控。

同时存在一处**可维护性缺陷**：页面切换的页 ID 数组 `['page-portal','page-home','page-workspace','page-datasource','page-payment-cycle','page-fund-occupancy']` 在 `index.html` 中以字面量重复硬编码 6 处（`goPortal` / `enterFromPortal` / `enterContract` / 资金页 / 回款页 / 手册页等）。新增任何页面都要改 6 处，漏改即出现「两个页面同时高亮」的显示 bug。

## 目标

1. 门户首页在视觉上分成两个带标题栏的分区：**经营管理**（财经侧）与**运维管理**（执行侧），当前归属为——运维管理仅「备品备件采购询比价」，其余全部归经营管理。
2. 经营管理区新增「项目全生命周期管理」入口卡片（CC-010），并在布局上体现其「大模块」地位。
3. 收敛页 ID 硬编码为单一 `showPage(id)` 入口，后续新增页面只需注册一次。

## 变更范围

### In Scope

- `frontend/index.html`：`#page-portal` 结构重组为「副标题 → 数据源横条 → 经营管理分区 → 运维管理分区」。
- `frontend/index.html`：新增 `ALL_PAGES` 注册表 + `showPage(pageId)` helper，替换 6 处重复的页 ID 字面量数组。
- `frontend/common.css`：新增分区容器、分区标题栏、分区配色变量与响应式栅格；新增 `feature` 型大卡片样式。
- `frontend/index.html` 用户手册「一、系统概述 / 模块清单」同步双分区措辞，并补 CC-010 章节索引。

### Out of Scope

- 不改动任何业务页面的内部逻辑（合同工作区、资金、回款、数据源、毛利率、备件采购）。
- 不改动后端接口与数据库。
- 不引入前端框架或构建工具，保持原生 HTML/JS + 单 CSS 的现状。
- 不做「用户可自定义分区/收藏卡片」的配置能力。

## 接口与数据契约

无后端接口变更。前端内部契约新增：

```js
// 页面注册表：新增页面只需在此登记一次
const ALL_PAGES = ['page-portal','page-home','page-workspace','page-datasource',
                   'page-payment-cycle','page-fund-occupancy'];
function showPage(pageId){ /* 隐藏 ALL_PAGES 全部 → 激活 pageId */ }
```

卡片归属数据（静态）：

| 分区 | 卡片 | 状态 |
|------|------|------|
| 经营管理 | 回款周期分析 / 资金占用·周转率 / 签单毛利率统计 / 项目决算报告 / 采购合同比对 / **项目全生命周期管理** | 已上线 ×4、即将上线 ×1、大模块 ×1（CC-010） |
| 运维管理 | 备品备件采购询比价 | 智能体 |

## 风险与兼容性

- 风险：`showPage()` 重构触及 6 处调用点，漏改会造成页面切换失效。缓解：以 `ALL_PAGES` 为唯一真源，并在冒烟测试中断言「任意时刻仅一个 `.active`」。
- 兼容性：卡片 `onclick` 行为与目标路由完全不变，仅布局层级变化；旧书签 `/gross`、`/procurement` 不受影响。
- 回滚：还原 `index.html` 的 `#page-portal` 段落与 `common.css` 追加的分区样式即可，无数据影响。
