# 合同比对系统 — 功能项文档

> 版本: v1.0 | 端口: 9006 | 最后更新: 2026-06-11

---

## 一、项目概述

B/S架构Web管理系统，以主合同硬件采购清单为唯一权威基准，自动比对供应商报价清单，识别差异并输出整改报告。

**核心业务链路：** 导入 → 智能比对 → 异常输出 → 供应商整改 → 迭代重比对 → 进度100%闭环

**用户角色：**
- 内部管理员：唯一操作人员，操作所有功能
- 供应商：不登录系统，接收导出的Excel整改报告

---

## 二、系统模块

| 模块 | 说明 |
|------|------|
| 合同基准库管理 | Excel导入合同清单，基准数据只读固化，支持重新导入覆盖 |
| 供应商报价版本管理 | Excel导入供应商报价，每次导入生成新版本，历史全部留痕 |
| 智能双向比对引擎 | 正向比对(合同→供应商) + 反向比对(供应商→合同) |
| 采购状态与进度统计 | 单条状态机 + 整单闭环判断 + 进度百分比 |
| 结果展示与报告导出 | 明细列表、筛选搜索、差异详情、一键导出整改Excel |

## 四、状态定义

### 4.1 单条条目状态

| 状态 | 判定条件 |
|------|----------|
| 匹配成功 | 型号一致 + 核心参数一致 + 数量一致 |
| 匹配异常 | 数量不匹配 / 型号不匹配 / 核心参数不匹配 / 金额不一致(可选) |
| 待采购 | 合同有、供应商无匹配 |
| 供应商增项 | 供应商有、合同无匹配 |

### 4.2 整单状态

- **未比对** — 刚导入，未执行比对
- **比对中** — 比对进行中
- **比对完成（存在异常）** — 有异常/待采购/增项
- **整单闭环完成** — 进度100%（匹配异常=0, 待采购=0, 全部增项已处置）

## 五、前端页面

### 5.1 首页总览看板

**统计卡片（6个）：**
- 合同总条目数
- 已匹配成功数
- 匹配异常数
- 待采购漏报数
- 供应商增项数
- 整体采购进度（进度条+百分比）

**图表：**
- 条目状态分布饼图
- 多版本迭代进度趋势图（折线图）

### 5.2 合同基准管理

- 上传Excel合同清单，**无列名约束**，传什么列显示什么列
- 智能映射：自动匹配 产品名称→设备名称、型号→设备型号、数量、单位、单价、金额 等
- 所有原始列数据完整保留（JSON存储），前端动态渲染表头
- **禁止页面编辑/删除**基准数据
- 重新导入覆盖旧数据

### 5.3 供应商版本管理

- 上传供应商报价Excel
- 每次上传自动生成新版本号
- 切换历史版本查看历次比对结果
- 历史版本不可覆盖，全部留痕

### 5.4 比对结果明细（核心页）

**列表字段：** 设备名称、型号、合同数量/报价数量、合同参数/报价参数、匹配状态、异常标签、异常详情、版本号

**筛选器：** 状态筛选（全部/匹配成功/匹配异常/待采购/供应商增项）、关键词搜索、版本号筛选

**操作：** 查看差异详情弹窗

### 5.5 整改报告导出

一键导出Excel，包含：
1. 全部异常条目 + 差异原因
2. 待采购漏报条目 + 补报提示
3. 供应商增项条目 + 删除提示
4. 当前整体采购进度
5. 标准化整改提示话术模板

## 六、Excel模板规范

**无列名强制约束**，上传Excel自动智能映射。列名别名覆盖：
- 产品名称/设备名称/品名 → 设备名称
- 型号/规格型号/型号规格 → 设备型号
- 功能要求/配置描述/详细参数/技术参数 → 规格参数
- 数量/采购数量 → 数量
- 单位 → 单位
- 单价/含税单价 → 单价
- 金额/含税金额/总价 → 金额
- 品牌/备注 → 备注

**导入兼容：**
- 自动过滤空行
- 自动跳过表头行
- 列名模糊匹配（含换行符），允许任意顺序
- 未匹配的列保留原始数据JSON存储
- 前端动态渲染所有列

---

## 七、系统约束

1. 合同基准前端禁止编辑/删除
2. 所有版本、比对结果永久留痕
3. 禁止覆盖历史版本数据
4. 进度基于**合同金额占比**计算，不用条目数
5. 所有异常必须输出文字描述
6. 比对引擎对合同 + 供应商 均进行参数结构化解析
7. **多合同数据完全隔离**，所有操作带contract_id


## 十、多合同管理扩展

### 10.1 业务流程

旧流程：进入系统 → 直接操作唯一合同
新流程：
1. 首页展示全部合同总概览 + 合同管理列表
2. 搜索/筛选合同，点击进入某份合同
3. 进入该合同独立工作空间，执行：上传基准、上传报价、比对、明细、导出
4. 每份合同数据、版本、比对结果完全隔离

### 10.2 合同主表 `contracts`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 合同ID |
| contract_name | TEXT | 合同名称 |
| contract_no | TEXT | 业务合同编号 |
| sign_date | TEXT | 签订日期 |
| total_amount | REAL | 合同总金额 |
| status | TEXT | 状态枚举 |
| created_at | TEXT | 创建时间 |
| updated_at | TEXT | 更新时间 |

**状态枚举：** 未上传基准 / 比对进行中 / 待供应商整改 / 已闭环(100%)

所有原有表（contract_items / supplier_items / comparison_results / versions）全部增加 `contract_id` 外键。

### 10.3 首页全局统计

| 统计卡片 | 说明 |
|----------|------|
| 合同总数 | 全部合同数量 |
| 已闭环 | 进度=100%的合同数 |
| 进行中 | 存在异常/待采购的合同数 |
| 总采购金额 | 全部合同金额合计 |

**合同列表字段：** 合同ID、合同名称、编号、签订日期、总金额、进度%、状态、统计摘要

**筛选条件：** 合同名称/编号搜索、状态筛选、日期范围

### 10.4 关键约束

1. 每份合同数据完全隔离，所有查询/比对/导出严格带 contract_id
2. 一个合同下可有多轮供应商报价版本
3. 删除合同：级联删除该合同下全部数据
4. 合同元信息可编辑；合同基准清单只读，仅可重新上传

### 10.5 存储方案

采用**数据库方案**（SQLite），所有表加 contract_id 外键隔离。多合同查询、筛选、聚合统计性能好，数据完整性可靠。
