# 合同比对系统 — 比对规则文档

> 版本: v1.0 | 最后更新: 2026-06-11

---

## 一、比对原则

1. **基准不可篡改** — 主合同清单 = 唯一权威基准，全部比对以此为准
2. **供应商可迭代** — 供应商清单支持多次上传，每次生成新版本
3. **双向比对** — 正向(合同→供应商) + 反向(供应商→合同)
4. **闭环终点** — 整单无异常、无漏报、无错配，进度100%

---

## 二、匹配主键规则

### 2.1 优先匹配键

```
匹配键 = 设备型号 + 设备名称
```

1. **设备型号完全一致** → 判定为同一条设备 → 进入字段详细比对
2. **型号不一致** → 直接标记 **【型号异常】**

### 2.2 匹配流程

```
合同条目.model + 合同条目.name
       ↓ 在供应商清单中查找
供应商条目.model + 供应商条目.name
       ↓
完全一致? ──Yes──→ 字段详细比对
       │
       No
       │
       ↓
  【型号异常】
```

## 三、字段比对规则

### 3.1 数量比对

| 条件 | 结果 |
|------|------|
| 报价数量 = 合同数量 | 正常 |
| 报价数量 < 合同数量 | **数量少报异常** |
| 报价数量 > 合同数量 | **数量多报异常** |

### 3.2 核心参数比对

#### 3.2.1 参数提取

从 `规格参数` 字段中提取结构化参数（CPU、内存、硬盘等）。**若无法提取结构化参数，则直接比对完整文本。**

#### 3.2.2 比对策略

| 场景 | 策略 |
|------|------|
| 能提取结构化参数 | 逐项比对 CPU/内存/硬盘/显卡/端口/功率 |
| 无法提取结构化参数 | 直接比对完整「规格参数/功能要求/配置描述」文本 |
| 描述性备注文本差异 | 不参与异常判定 |

#### 3.2.3 单位归一化规则

| 原始值 | 归一化 | 说明 |
|--------|--------|------|
| 32G | 32GB | G→GB |
| 32g | 32GB | 大小写不敏感 |
| 1T | 1TB | T→TB |
| 4核 | 4cores | 中文核→cores |
| 4Core | 4cores | 大小写统一 |
| 2×16GB | 32GB | 组合表达式展开 |

#### 3.2.3 比对判定

| 条件 | 结果 |
|------|------|
| 所有核心参数一致（归一化后） | **参数正常** |
| 任一核心参数不一致 | **【参数异常】**标注具体差异 |
| 描述性备注文本差异 | **不参与异常判定** |

### 3.3 型号规格比对

- **字符串严格比对**（去首尾空格后）
- 不一致 → **【型号异常】**
- 型号包含关系也算不一致（如 "SR650" vs "SR650 V2"）

### 3.4 金额比对（功能开关）

| 开关状态 | 行为 |
|----------|------|
| **关闭（默认）** | 仅校验硬件参数、数量，不比对金额 |
| **开启** | 单价、总价差异标记异常 |

## 四、双向比对流程

### 4.1 正向比对（合同 → 供应商）

```
遍历全部合同基准条目:
    根据(型号+名称)查找供应商清单对应条目
    ├── 找到 ──→ 执行字段比对
    │            ├── 全部一致 → 匹配成功
    │            └── 有差异   → 匹配异常
    └── 未找到 ──→ 待采购（供应商漏报）
```

### 4.2 反向比对（供应商 → 合同）

```
遍历全部供应商报价条目:
    在合同基准中做(型号+名称)匹配
    ├── 找到 ──→ 跳过（已在正向比对中处理）
    └── 未找到 ──→ 供应商额外增项
```

### 4.3 去重规则

- 正向比对已处理过的配对，反向比对**不再重复判定**
- 同一个合同条目匹配到多个供应商条目时，取**第一个匹配**

---

## 五、进度计算公式

```
整体采购进度 = (匹配成功条目合同总金额 ÷ 合同全部总金额) × 100%
```

- 异常、待采购、供应商增项 → **不计入完成金额**
- 匹配成功条目的**合同金额**（非报价金额）计入分子
- 结果保留 **2位小数**
- 不使用条目数量占比

### 示例

```
合同总金额: 1,000,000 元
成功匹配条目合同金额合计: 850,000 元
进度 = 850,000 / 1,000,000 × 100% = 85.00%
```

## 六、异常文案模板

| 异常类型 | 固定文案 |
|----------|----------|
| 数量异常 | 合同数量{X}，供应商报价数量{Y}，数量不一致 |
| 型号异常 | 设备型号与合同基准不匹配 |
| 参数异常 | 核心参数（CPU/内存/硬盘）不符合合同要求 |
| 待采购漏报 | 合同存在该设备，供应商未报价，需补报 |
| 供应商增项 | 该设备不在合同采购范围内，属于私自新增条目，需删除 |

---

## 七、迭代比对规则

1. 首次比对 → 产生异常/待采购/增项 → 导出整改报告
2. 供应商修改后管理员上传新版本
3. 系统执行**新一轮完整比对**（不参考历史结果）
4. 问题修复条目自动更新为【匹配成功】
5. 未修复条目保持异常状态
6. 循环直到：无异常 + 无待采购 + 全部增项已处置 → 进度100%

---

## 八、版本记录规则

每次上传供应商报价Excel：
1. 自动生成新版本号（自增整数）
2. 自动记录上传时间
3. 计算并保存：总条目、匹配数、异常数、待采购数、增项数、进度%
4. 历史版本数据**不可覆盖、不可删除**
