## 0. 目的与目标

统一"经营业务"的数据地基：以**项目**为主数据/本体根，把所有业务（售前/合同/采购/财务/人力/比对）围绕它收敛成一套**共享语义 + 数据契约**，为后续智能体生态提供一致的领域边界。

## 1. 决策记录（AD）

| # | 决策 | 结论 |
|---|------|------|
| AD-1 | 商机号/合同号/项目号 | **三号各自独立**。售前用商机号、签订用合同号、执行用项目号 |
| AD-2 | 主数据锚点 | **项目＝主数据**；大部分项目号直接沿用合同号，少数项目号与合同号不同。后续口径一律按**项目** |
| AD-3 | 项目↔合同关系 | 以 **1:1** 起步；模型**预留一对多（子项目）余量** |
| AD-4 | 本体形态 | 采用**轻量领域模型 + 数据契约**开局；自动推理（本体论层）**后置**按需叠加 |
| AD-5 | 前端统一规范 | 导航统一**标准面包屑**（去左侧树/手风琴/侧栏）；图标统一**扁平线性**图标库（现已拍板，纳入本草案附录执行） |

## 2. 三号链路与语义

```
商机号 opp_no ──中标晋升──▶ 合同号 contract_no ──立项──▶ 项目号 project_no (主数据, 唯一)
   （售前）               （签订）                    （执行；多数=合同号，少数不同）
```

- 三号均为**独立字段**，项目主数据同时持有 `project_no / contract_no / opportunity_no` 作为链路引用，保证"商机≠合同、多数项目=合同、少数例外"都成立且可溯源。
- `project_no` 是**唯一标识（业务主键）**；内部另有全局 `project_id`（代理键）供关系用。

## 3. 领域模型（本体 v0）

### 3.1 聚合 / 实体划分（以项目为 Aggregate Root）

```
Project（根）  ◀── 主数据/本体；唯一锚点
├─ Opportunity（售前：商机号、状态、投标概算、售前资料）        ↤ 合同/立项 来源
├─ Contract（合同号、签署信息；1:1，预留 SubProject）          ↤ 签订主属性
│   └─ SubProject（子项目；一对多余量，默认空）
├─ Baseline/四算（概算/预算/核算/决算 + 分项 + 锁定留痕）       ── 预算/控成本
├─ Milestone & Task（粗/细里程碑、任务、双维度进度）            ── PMO
├─ Purchase（询比价任务/报价/供应商/硬件采购对比）              ── 采购域
├─ Finance（成本归集、回款/应收、毛利、决算；台账）             ── 财经域
├─ HR（人员分配、工时填报、人力成本、负荷）                     ── 人力域
├─ Ops（运维域：项目联系人/收件人/现场地址/联系方式、服务响应）  ── 运维域
├─ Alert / Config / Dict / OpLog（预警、配置、字典、操作日志）  ── 横切
```

### 3.2 关键实体与属性（草案字段）

| 实体 | 关键属性 | 备注 |
|------|----------|------|
| **Project** | project_id, project_no(唯一), contract_no, opportunity_no, contract_id, parent_project_id(子项目), name, customer_key, status, owner_ref(项目经理引用,不携带联系方式), dept, sign_amount/date, cycle, created/updated | 主数据；承接合同固有属性并口径统一。**联系方式/收件人/地址不在此维护**，归 Ops 运维域 |
| Opportunity | opp_no, project_id(可空/立项后回填), status(跟进/投标/中标/流标), estimate(budget 概算), presale_docs | 售前 |
| Contract | contract_id, project_id, contract_no, sign_amount/date, 甲方/乙方, terms | 1:1↔Project；预留 SubProject |
| Baseline | project_id, 四算字段(概算/预算/核算/决算), lock_flag, source(商机概算溯源), 变更日志 | 核算/决算本期仅占位 |
| Milestone/Task | project_id, level(粗/细), plan/actual dates, progress, owner, 关键标记 | PMO |
| Purchase | project_id(替代原 contract 关联), inquiry 任务/报价/供应商/对比项 | 采购域映射 |
| Finance | project_id, cost/income/毛利, 回款/应收, ledger | 财经域 |
| HR | project_id, staff/assignment/timesheet/人力成本 | 人力域 |
| Ops | project_id, contact（角色/姓名/电话/收件地址/现场地址）, 服务响应记录 | **运维域**：项目联系人、项目经理/收件人联系方式由运维维护，不作为主数据字段 |
| Dictionary/Config/AlertRule/OpLog | — | 横切，统一字典 |

### 3.3 关系

- Project—Contract：**1:1**（默认），预留 `parent_project_id` 支持 **1:N 子项目**。
- Opportunity—Project：N:1（多商机竞标同一合同/项目）或 1:1 晋升，由源跟踪。
- Project—Ops：1:N（一个项目可有多个联系人：项目经理/收件人/现场负责人等）；**联系信息由运维域维护**。
- 所有从属域（Baseline/Milestone/Purchase/Finance/HR/Ops/…）**仅通过 `project_id` 关联**，不直接连合同/商机。
- 跨域统计口径统一取 `Project`（项目口径）。

### 3.4 字典 / 枚举（统一）

- 项目状态：待启动 / 执行中 / 暂停 / 结项
- 商机状态：跟进中 / 投标中 / 中标 / 流标
- 里程碑状态：未开始 / 进行中 / 已完成 / 延期
- 四算口径：概算 / 预算 / 核算 / 决算（核对预留）
- 成本归集类别：人力 / 分包 / 硬件 / 软件 / 服务 / 其他
- 运维联系人角色：项目经理 / 收件人 / 现场负责人 / 商务对接

## 4. 现状映射（三张"合同" → 项目主数据）

| 现表 | 现归属 | 并法（映射/视图） |
|------|--------|-------------------|
| `plm_contract / plm_project` | 生命周期 | **升级为新主数据（Project）** 的来源与落点 |
| `procurement_contract` | 采购 | 收敛为"采购侧视图"，字段回归主数据；采购任务只留 `project_id`。**收件人/联系方式/邮寄地址迁往 Ops 运维域**，采购确认邮件按需从其取 |
| `contracts`（比对） | 硬件采购对比 | 变为"Project → 采购对比/表项/供应商版本"聚合，不再当独立合同 |
| `plm_*`（baseline/milestone/task/ledger/timesheet…） | 生命周期 | 全部改 `project_id` 关联 |

> 原则：**先以项目主数据做映射/视图层，业务仍可读写**；物理表分期迁移，现网功能不受影响。

## 5. 数据契约（API 统一方向）

- 统一资源：`/api/project/{project_id}/{domain}...`
- 各业务域间只通过 `project_id` 传递，不再散传 `contract_no` 字符串。
- 枚举/字典走统一 `/api/dict`。
- **采购依赖 Ops 取数（已确认）**：采购确认邮件所需的收件人/联系方式/邮寄地址，由 `项目(project_id) → Ops 运维域` 提供，不再取自采购合同字段。迁移时把存量 `procurement_contract.receiver_*` 数据搬入 Ops。

## 6. 分期路线（大工程，谨慎推进）

| 期 | 内容 | 交付 |
|----|------|------|
| P0 | 领域模型定稿（本文档评审通过）| 模型 + ER + 字典 + 迁移映射（**含 Ops 域及采购依赖取数**）|
| P1 | 主数据就位 | Project 主数据表/服务、三号链路、审计留痕、Ops 联系信息域、迁移工具 |
| P2 | 业务域挂接 | PLM→采购→比对→财经/人力/运维逐一改 `project_id` |
| P3 | 统一与收尾 | 废弃旧合同表、统一门户入口与面包屑/图标规范 |

> 每一步保持现有功能可用，可灰度。

## 7. 风险与开放问题

- **成本归集与会算**：核算/决算本期仅占位，转到哪些域会先冲突需先定水平。
- **采购与 PLM 是否共享"项目"单点更新**：单一事实源确定后，权限/并发留意。
- **子项目余量**：1:1 起步，`parent_project_id` 预留；需在 P1 明确子项目语义（是否独立编号/独立预算口径）。
- **口径变更**：由"合同口径"全面切"项目口径"，涉及报表/比对/毛利等存量统计，需迁移脚本与对账。
